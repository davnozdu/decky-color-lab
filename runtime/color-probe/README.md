# Экспериментальная адаптивная цветокоррекция с NPU

16 ноября 2026, Ally / CachyOS, Ryzen AI runtime 1.9. Живая картинка игры
не изменялась. Подготовлены модель анализа, её аппаратный запуск, статическая
цветовая таблица и offline-пример для снимка RDR2.

## Что работает

Использованы опубликованные unpaired sRGB-веса проекта
[Image-Adaptive-3DLUT](https://github.com/HuiZeng/Image-Adaptive-3DLUT),
commit `b491f6df64a588864739a157db271e5c848e1805`, Apache-2.0.
Лицензия сохранена в `LICENSE.upstream`. Веса загружались через
`torch.load(..., weights_only=True)`, пользовательские модели не обучались.

Небольшой CNN (269,635 параметров) анализирует RGB 256×256 и выдаёт три
коэффициента смешивания обученных 3D LUT. Применять полученную LUT к полному
кадру можно отдельно от анализа. Вычисление анализа не обязано запускаться
на каждом кадре или задерживать рендер.

## Аппаратная проверка

InstanceNorm выписан через mean/variance/affine с сохранением весов; CPU PyTorch
проверка против исходной операции дала max error 6.52e-7. Это не удаление нормы
или замена обученного поведения на приближение.

Строгая NPU-only сессия отказалась запускаться: нормализация не была перенесена.
Разрешённый диагностический гибрид дал два NPU-подграфа свёрток и CPU-операции
ReduceMean, Sub, Mul, Add, Sqrt, Div. Это **CPU + NPU**, не полностью NPU.

Предварительные замеры 20 вызовов, только анализ готовой миниатюры:

| Исполнение | Время анализа | CPU-время на анализ |
|---|---:|---:|
| CPU | 5.747 мс | 5.068 мс |
| CPU + NPU | 5.769 мс | 3.845 мс |

CPU-время в этом замере уменьшилось, задержка практически та же. Это не
контролируемый повторный энергетический тест и не доказательство выигрыша
GPU/батареи: захват миниатюры, обновление LUT и применение ко всем кадрам
не измерены. При частоте анализа раз в секунду абсолютная экономия CPU
составляла бы лишь около 1.2 мс/с, до учёта остальных этапов.

Коэффициенты на тестовом снимке:

- CPU: `[1.5730144, 0.0531303, -0.2437324]`.
- CPU + NPU: `[1.5703125, 0.0341797, -0.2441406]`.

Максимальное отличие коэффициента 0.01895. Это численная проверка на одном
снимке, не проверка визуальной стабильности или качества для всех игр.

## Подготовленные артефакты

- `lut-classifier.onnx`: анализатор.
- `npu-look.cube`: 33³ LUT, выбранная моделью CPU+NPU; сила эффекта 25%,
  смешивание с настоящей identity LUT, значения ограничены 0…1.
- `comparison-original-left-npu-right.jpg`: слева оригинал, справа эффект.
- `npu-look-preview.png`: обработанный снимок без сравнения.
- `look-metadata.json`: коэффициенты, сила и область применимости.
- `runs/`: исходные логи, ORT-профили, рассчитанные коэффициенты.

Порядок осей LUT проверен: identity-преобразование сохраняет вход с ошибкой
не более 1e-5. Для offline-превью LUT применена программно, не в игре.
Это **SDR цвет/тон**, не восстановление HDR-деталей, не изменение возможностей
панели и не объективно гарантированное улучшение авторской картинки игры.

Установленный Gamescope показывает команду `set_look` для `.cube`. Она не
вызывалась: файл в живом игровом сеансе не активирован. Совместимость цветового
пространства, стоимость применения, захват миниатюры и сглаживание адаптации
нужно проверить отдельно. Экономия батареи и отсутствие просадок не доказаны.

## Воспроизведение

На машине с PyTorch/ONNX: `python3 color-probe/export.py` из корня проекта.
Скрипт использует исходники/веса в `framegen-probe/hf-candidates/` и снимок
`motion-probe/game-before.png`. На Ally:

```bash
cd ~/AsusNPU/color-probe
bash build.sh
source ../framegen-probe/runtime.sh
root="$PWD"
mkdir -p runs/manual
cd runs/manual
COLOR_ALLOW_CPU=1 "$root/color-probe" "$root/lut-classifier.onnx" \
  "$root/input.bin" weights.bin "$root/cache" \
  "$root/../framegen-probe/bf16-config.json" 20
```

`COLOR_CPU=1` задаёт чистый CPU-референс. Без `COLOR_ALLOW_CPU` сессия строго
запрещает CPU fallback и сейчас ожидаемо отказывается запускаться.
`make_lut.py --weights PATH --strength 0.25` создаёт offline-таблицу/превью.

Следующий этап — редкий асинхронный анализ, временное сглаживание коэффициентов
и применение LUT средствами композитора с A/B-замером FPS и всей мощности
батареи при неизменной сцене и TDP. До этого результат — рабочая модельная
проба и визуальный пример, не готовый игровой сервис.
